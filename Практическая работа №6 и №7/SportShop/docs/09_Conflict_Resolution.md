# Разрешение конфликта в total_sum

## Причина конфликта

От ветки develop были созданы две независимые ветки:

- feature/total-v1 — реализовала функцию total_sum без учёта количества;
- feature/total-v2 — реализовала ту же функцию, но с учётом количества.

Обе ветки изменяли один и тот же участок файла shop.py. При слиянии Git не смог автоматически определить, какую версию оставить, и создал конфликт слияния.

## Как выглядел конфликт

После команд:

    git checkout develop
    git merge feature/total-v1
    git merge feature/total-v2

Git вывел сообщение:

    Auto-merging shop.py
    CONFLICT (content): Merge conflict in shop.py
    Automatic merge failed; fix conflicts and then commit the result.

В файле shop.py появились маркеры конфликта:

    <<<<<<< HEAD
    def total_sum(products):
        return sum(p['price'] for p in products)
    =======
    def total_sum(products):
        return sum(p['price'] * p['quantity'] for p in products)
    >>>>>>> feature/total-v2

Что означают маркеры:

- <<<<<<< HEAD — начало версии из текущей ветки develop.
- ======= — разделитель между двумя версиями.
- >>>>>>> feature/total-v2 — конец версии из сливаемой ветки.

## Как конфликт был разрешён

Нужно выбрать одну из версий или объединить их. В нашем случае правильная версия — из feature/total-v2, потому что она учитывает количество товара.

Шаги:

1. Открыть shop.py в VS Code.
2. Найти маркеры конфликта.
3. Удалить маркеры и ненужную версию.
4. Оставить правильный вариант:

    def total_sum(products):
        return sum(p['price'] * p['quantity'] for p in products)

5. Сохранить файл (Ctrl+S).
6. Добавить изменения в индекс:

    git add shop.py

7. Завершить слияние коммитом:

    git commit -m "Разрешён конфликт в total_sum"

## Проверка результата

После коммита:

    git log --oneline --graph

В истории видно слияние и коммит с разрешением конфликта.

Функция total_sum в shop.py теперь работает корректно — учитывает количество товара.

## Вывод

Конфликт слияния возникает, когда две ветки изменяют один и тот же участок кода. Git не может выбрать правильную версию автоматически и оставляет маркеры конфликта, чтобы разработчик разрешил его вручную.

Порядок разрешения:

1. Открыть файл с конфликтом.
2. Выбрать правильную версию или объединить обе.
3. Удалить маркеры.
4. Сохранить файл.
5. Выполнить git add и git commit.

В нашем случае оставлена версия с учётом количества — она корректнее и даёт правильную итоговую сумму.
