# Обработка ошибок интеграции

## Какая ошибка была внесена

В файле src/cart.py в функции add_to_cart был изменён ключ при создании элемента корзины.

Было (правильно):

    cart.append({
        'id': product_id,
        'name': product['name'],
        'price': product['price'],
        'size': size,
        'quantity': quantity,
    })

Стало (с ошибкой):

    cart.append({
        'id': product_id,
        'product': product['name'],
        'price': product['price'],
        'size': size,
        'quantity': quantity,
    })

Ключ 'name' был заменён на 'product'. Остальные модули (orders.py, analytics.py, print_order) ожидают ключ 'name' и не находят его.

## Как ошибка проявилась

После внесения ошибки были запущены интеграционные тесты:

    python -m unittest discover -s tests

Результат — один тест упал:

    FAIL: test_full_cycle (tests.test_integration.TestIntegration.test_full_cycle)
    Полный цикл: загрузка → корзина → заказ → сохранение → загрузка.
    ----------------------------------------------------------------------
    AssertionError: 'name' not found in {'id': 1, 'product': 'Air Max',
    'price': 8990.0, 'size': '36.0', 'quantity': 1}

    Ran 30 tests in 0.005s

    FAILED (failures=1)

Ошибка возникла в тесте test_full_cycle на строке:

    self.assertIn('name', order['items'][0])

Тест проверял, что в элементе заказа есть ключ 'name'. После внесения ошибки ключ стал 'product', и тест упал с AssertionError.

Остальные 29 тестов прошли — значит, ошибка затрагивает только поле 'name', не влияя на сумму заказа (order['total'] считается через price × quantity).

## Как была исправлена

1. Открыт файл src/cart.py.
2. Найдена строка с ключом 'product' в функции add_to_cart.
3. Ключ заменён обратно на 'name':

       'name': product['name'],

4. Файл сохранён.
5. Тесты перезапущены:

       python -m unittest discover -s tests

   Результат — OK, все 30 тестов прошли.

## Вывод

Интеграционные тесты позволяют обнаружить несовместимость модулей, которая не видна при модульном тестировании. Каждый модуль по отдельности может работать правильно, но при совместной работе возникают ошибки:

- разные имена полей (name vs product);
- разные форматы данных;
- разные соглашения о структуре.

В нашем случае ошибка была найдена автоматически благодаря интеграционному тесту test_full_cycle, который проверяет не только итоговую сумму заказа, но и структуру элементов корзины.

Важный вывод: интеграционные тесты должны проверять не только итоговые значения (сумму, количество), но и структуру данных (наличие полей, их имена, типы). Иначе ошибка в названии ключа останется незамеченной.
